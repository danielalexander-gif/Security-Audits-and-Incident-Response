# NIST Incident Report: ICMP Flood Attack

## Incident Summary
Network services were halted due to a Denial of Service (DoS) ICMP flood attack. The incident response team took all non-essential network systems offline to mitigate the attack and restore affected essential services. The post-incident investigation revealed that the threat actor gained access through a misconfigured firewall, which permitted the overwhelming influx of ICMP packets. 

To prevent future incidents, the firewall was reconfigured with a strict rule limit on incoming ICMP packets, and source IP verification was enabled to block potentially spoofed addresses. Additionally, Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) were deployed to automatically filter suspicious ICMP traffic.

## NIST Cybersecurity Framework (CSF) Analysis

*   **Identify:** The event was classified as a DoS ICMP flood based on the irregularly high volume of ICMP packets preceding the system failure. The initial penetration point was identified as an unconfigured firewall.
*   **Protect:** To secure the network moving forward, the newly configured firewall must undergo periodic maintenance to ensure its security posture remains strong. 
*   **Detect:** The newly implemented IDS and IPS, working alongside the reinforced firewall, are now positioned to actively detect and prevent unusual network traffic.
*   **Respond:** The initial vulnerability has been remediated. Future responses will be dictated by alerts generated by the IDS/IPS systems, which require prompt follow-up.
*   **Recover:** The response team successfully recovered network services by temporarily taking systems offline, which halted the ICMP flood and allowed for the safe restoration of essential operations.
